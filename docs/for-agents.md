# Using diagrams-as-code from an AI agent or a program

This guide is for software that writes diagrams: language-model agents, build scripts, notebooks. It is exact rather than friendly. Every `python` and `bash` block below is executed by `tests/test_for_agents_doc.py`, so a snippet that stops working fails the build. (Blocks marked `file=NAME` are written to disk and then imported and checked for a `diagram()` function.)

Machine-readable entry points:

- [`llms.txt`](https://bsommers.github.io/diagrams-as-code/llms.txt) and [`llms-full.txt`](https://bsommers.github.io/diagrams-as-code/llms-full.txt): the whole documentation in one fetch.
- [`api-reference.md`](api-reference.md): signature and docstring of every public name.
- [`examples/index.json`](../examples/index.json): one record per example script.
- [`capabilities.json`](capabilities.json): what the library can do, with the module and test that prove each claim.

All are regenerated by `uv run python tools/build_agent_docs.py` and checked with `--check`.

## 1. Choose an interface

| Interface | Use it when | Contract |
|---|---|---|
| **Python API** | You are already in Python and want exceptions, the `Diagram` object, or a custom loop. | `import diagrams_as_code`. Errors are exceptions (`ValueError`, `KeyError`, `MathError`, `PDFExportError`). Nothing is printed. |
| **CLI** | You can write a script file and shell out. Best for render, lint and batch work. | `diagrams-as-code <command>`. See below. |
| **MCP server** | Your client speaks the Model Context Protocol and cannot run a shell. | `diagrams-as-code mcp --root DIR`; JSON-RPC 2.0 over stdio. Scripts must already exist under `DIR`. |

The CLI contract:

- **stdout**: `render` prints one `wrote <path>` line per file; `lint` prints one `<script>: <kind>: <detail>` line per finding plus a summary line (`--quiet` drops the summary); `themes` prints one name per line; `icons` prints `name<TAB>domain<TAB>description`.
- **stderr**: every failure, as `error: <path>: <message>` (add `--debug` for a traceback).
- **exit code**: `0` success; `1` a script failed to load or render, `lint` found something, or no diagram script was found; `2` a usage error (bad flag, missing file argument).
- A *diagram script* is a `.py` file that defines `diagram()` returning a `Diagram`. When scanning a directory the CLI skips `.py` files without `diagram()`. A module-level `OUTPUT_STEM = "name"` sets the output file name; the default is the script's stem.

Run `diagrams-as-code <command> --help` for the flags your installed version has.

```bash runnable
diagrams-as-code themes
diagrams-as-code icons --domain iiot
```

## 2. A minimal verified quickstart

Write a script that defines `diagram()`:

```python runnable file=hello.py
from diagrams_as_code import Diagram, Shape


def diagram() -> Diagram:
    with Diagram("Request path", theme="paper", layout="auto") as d:
        web = d.add(Shape("web", "Web"))
        api = d.add(Shape("api", "API"))
        db = d.add(Shape("db", "Database", icon="database"))
        web >> d.edge("HTTPS") >> api
        api >> d.edge("SQL") >> db
    return d
```

Render it, then lint it:

```bash runnable
diagrams-as-code render hello.py --out out --format svg,png,bom
diagrams-as-code lint hello.py
```

`out/hello.svg`, `out/hello.png` and `out/hello_README.md` (the bill of materials) now exist. PNG needs one rasteriser (`resvg-py`, `cairosvg`, `inkscape` or `magick`); `uv sync` installs `resvg-py` for development. SVG, PDF and BOM need nothing.

## 3. API cheat sheet: the 15 calls you will use most

| # | Call | Does |
|---|---|---|
| 1 | `Diagram(title, theme="iiot_dark_gold", layout="manual", direction="LR")` | The canvas. Use it as a context manager. `layout="auto"` places unpinned shapes from the edges. |
| 2 | `d.shape(label, kind="box", icon=None, id=None, width=130, height=60)` | Create and add a node; returns the `Shape`. |
| 3 | `d.add(Shape(id, label, icon=...))` | Add a node you built yourself. Ids must be unique. |
| 4 | `a >> d.edge("label") >> b` | Connect two nodes. The edge exists only after the full chain `a >> edge >> b`. |
| 5 | `d.connect(a, b, label="")` | The same as 4, as a plain call; returns the `Edge`. |
| 6 | `with d.group("Title") as g:` | Draw a box around the shapes created inside the block. Groups nest. |
| 7 | `shape.at(x, y)`, `.below(other, margin=)`, `.right_of(other, margin=)` | Place a shape. `.at` pins it; the relative forms chain from another shape. |
| 8 | `d.text("...")`, `d.caption("...")` | Free text and a figure caption. Both take label markup (`**bold**`, `$math$`). |
| 9 | `d.render_svg(path=None)` | Returns the SVG string and writes it when `path` is given. |
| 10 | `d.render_png(path)`, `d.render_pdf(path=None)` | PNG (needs a rasteriser) and vector PDF (pure stdlib). |
| 11 | `render_all(d, out_dir, stem, formats=("svg", "png", "bom"))` | Write several formats; returns `{format: Path}`. Formats: `svg png pdf bom`. |
| 12 | `d.configure(theme=, layout=, direction=)` | Change settings after construction; returns the diagram. |
| 13 | `list_themes()`, `get_theme(name)` | Valid theme names. An unknown name does not raise (see pitfalls). |
| 14 | `audit_findings(d)` | Visual defects as `Finding(kind, detail)` objects. Empty list means clean. |
| 15 | `SequenceDiagram(title)` then `.participant()`, `.message()`, `.reply()`, `.build()` | A UML sequence diagram; `build()` returns a normal `Diagram`. |

Calls 1 to 14 in one verified block:

```python runnable
from pathlib import Path

from diagrams_as_code import Diagram, get_theme, list_themes
from diagrams_as_code.audit import audit_findings
from diagrams_as_code.output import render_all

with Diagram("Cheat sheet", theme="paper", layout="auto", direction="LR") as d:
    with d.group("Plant") as plant:
        sensor = d.shape("Sensor", icon="sensor", id="sensor")
        gateway = d.shape("Gateway", icon="gateway", id="gateway")
    cloud = d.shape("Cloud", kind="box", icon="cloud", id="cloud")
    sensor >> d.edge("OPC UA") >> gateway
    d.connect(gateway, cloud, label="MQTT")
    d.caption("**Figure 1:** a sensor reaches the cloud")

assert {s.id for s in d.shapes} >= {"sensor", "gateway", "cloud"} and len(d.edges) == 2
d.configure(theme="iiot_light")
assert d.theme.name == "iiot_light" and "iiot_light" in list_themes()
assert get_theme("paper").name == "paper"

svg = d.render_svg("cheat/figure.svg")
assert svg.startswith("<svg") and Path("cheat/figure.svg").read_text() == svg
d.render_pdf("cheat/figure.pdf")
written = render_all(d, "cheat", "figure", formats=("svg", "pdf", "bom"))
assert set(written) == {"svg", "pdf", "bom"}
assert audit_findings(d) == []

with Diagram("Pinned") as pinned:
    a = pinned.shape("A").at(40, 40)
    b = pinned.shape("B").right_of(a, margin=60)
    c = pinned.shape("C").below(a, margin=40)
    a >> pinned.edge() >> b
assert b.bounds.x > a.bounds.x and c.bounds.y > a.bounds.y
```

Call 15, a sequence diagram:

```python runnable
from diagrams_as_code.sequence import SequenceDiagram

seq = SequenceDiagram("Login", theme="iiot_light")
user = seq.actor("User")
app = seq.participant("App")
seq.message(user, app, "POST /login", activate=True)
seq.reply(app, user, "200 token")
diag = seq.build()
assert "<svg" in diag.render_svg()
```

The other kits are separate modules: `diagrams_as_code.plot.Plot` (data-space plots), `diagrams_as_code.draft` (dimension lines, hatching), `diagrams_as_code.gantt.GanttChart` (schedules; pass `today=` explicitly) and the math typesetter in `diagrams_as_code.text`. See [`api-reference.md`](api-reference.md) and the [math markup reference](math-markup.md).

## 4. The render and lint feedback loop

A diagram can run without error and still look wrong. Close the loop in five steps:

1. **Render** to SVG and PNG: `diagrams-as-code render script.py --out out --format svg,png`.
2. **Rasterise and inspect.** If you can read images, open the PNG: look for lines through boxes, clipped labels, empty canvas. Passing tests are not evidence that a diagram looks right.
3. **Lint.** `diagrams-as-code lint script.py` prints each defect and exits `1` if there is any, `0` if clean. Defect kinds: `edge_through_node`, `edge_through_own_endpoint`, `tangent_arrival`, `edge_on_edge`, `edge_through_badge`, `badge_over_node`, `badge_over_badge`, `badge_over_title`, `edge_through_title`, `title_overflow`, `label_overflow`, `node_overlap`, `group_overlap`, `content_clipped`, `canvas_mostly_empty`. Use `--ignore KIND[,KIND]` to silence a kind you accept.
4. **Fix** the cause named in the finding: move or resize a shape, shorten a label, add a waypoint or change the layout.
5. **Repeat** until lint exits `0`.

A script with a deliberate defect (two shapes pinned on top of each other):

```python runnable file=overlap.py
from diagrams_as_code import Diagram


def diagram() -> Diagram:
    with Diagram("Overlap", theme="paper") as d:
        d.shape("First").at(40, 40)
        d.shape("Second").at(60, 50)
    return d
```

```bash runnable exit=1
diagrams-as-code lint overlap.py
```

The same check from Python, which is the form to use inside a self-correcting loop:

```python runnable
import importlib.util

from diagrams_as_code.audit import audit_findings

spec = importlib.util.spec_from_file_location("overlap", "overlap.py")
module = importlib.util.module_from_spec(spec)
spec.loader.exec_module(module)
findings = audit_findings(module.diagram())
assert any(f.kind == "node_overlap" for f in findings)
for f in findings:
    print(f.kind, "-", f.detail)
```

## 5. Pitfalls

**Method names that do not exist.** These are guessed often and all raise `AttributeError`. Use the right-hand column.

| Do not write | Write instead |
|---|---|
| `Diagram.add_node(...)` | `d.add(Shape(id, label, icon=...))` or `d.shape(label, ...)` |
| `Diagram.add_edge(a, b)` | `a >> d.edge("label") >> b` or `d.connect(a, b)` |
| `add_shape`, `node`, `link`, `add_group`, `subgraph`, `cluster` | `d.shape`, `d.connect`, `d.group` |
| `d.save(path)`, `d.write(path)`, `d.export(...)`, `d.render(...)`, `d.draw()`, `d.to_svg()`, `d.to_png()` | `d.render_svg(path)`, `d.render_png(path)`, `d.render_pdf(path)`, `render_all(...)` |
| `d.set_theme(name)` | `Diagram(..., theme=name)` or `d.configure(theme=name)` |

```python runnable
from diagrams_as_code import Diagram

for name in ("add_node", "add_edge", "add_shape", "node", "link", "add_group", "subgraph", "cluster",
             "save", "write", "export", "render", "draw", "to_svg", "to_png", "set_theme"):
    assert not hasattr(Diagram, name), name
```

**Other traps, each checked against the code:**

- **An edge needs both ends.** `a >> d.edge("x")` alone records nothing; only `a >> d.edge("x") >> b` does.
- **An unknown theme name does not raise.** `Diagram("t", theme="dark")` silently falls back to `iiot_dark_gold`, a dark theme. Take names from `list_themes()`; the CLI `--theme` flag does validate.
- **The default theme is dark.** For textbook, paper or print figures pass `theme="paper"` (black on white, square corners, no shadows). The other light themes are `iiot_light`, `monochrome`, `solarized_light` and `pastel_light`.
- **Unicode subscripts and superscripts do not reach the PDF.** PDF export uses the 14 standard fonts, so a character such as `₂` is drawn as `?` and a warning is emitted. Use math markup instead: `$\ce{H2O}$`, `$x_1$`. The SVG and PNG look right either way, which hides the problem until the PDF.
- **Math markup is strict.** Text between `$ $` is typeset; an unsupported command raises `MathError` naming it. A lone `$` (`"Under $50k"`) stays text; write a literal pair as `\$`. See [math-markup.md](math-markup.md).
- **Unknown icons raise `KeyError`** at render time and list the valid names. Get them from `diagrams-as-code icons`.
- **Do not put helper modules in `examples/<domain>/`.** The gallery audit (`tools/audit_gallery.py`), the site build and the example tests treat every `*.py` there as a diagram script and call `diagram()` on it. The CLI skips such files, but the audit does not. Keep shared code outside `examples/`.
- **Output stems must be unique.** Two scripts rendering to the same directory with the same stem make `render` fail on the second one (`rename one script or set OUTPUT_STEM`).
- **Leave `width` and `height` off.** The canvas fits the content; a given size is only a minimum.
- **PNG needs a rasteriser** and raises `RuntimeError` naming the options when none is installed.

```python runnable
import warnings

from diagrams_as_code import Diagram, get_theme

assert Diagram("t", theme="dark").theme.name == get_theme("iiot_dark_gold").name

with Diagram("t", theme="paper") as d:
    a = d.shape("H₂O")
    b = d.shape("done")
    _half = a >> d.edge("x")
assert d.edges == []
with warnings.catch_warnings(record=True) as caught:
    warnings.simplefilter("always")
    d.render_pdf("subscript.pdf")
assert any("drawn as '?'" in str(w.message) for w in caught)

try:
    with Diagram("t") as bad:
        bad.shape("x", icon="no-such-icon")
    bad.render_svg()
except KeyError:
    pass
else:
    raise AssertionError("an unknown icon must raise KeyError")
```

## 6. Determinism guarantees

- **Same input, same bytes.** Rendering the same script twice gives byte-identical SVG and BOM files. The repository enforces this: `git diff --exit-code -- examples/` must be empty after `uv run python main.py`.
- **No clock, no randomness.** The library never reads the time or draws random numbers. `GanttChart` needs an explicit `today=` date for its "today" line.
- **Layout is stable.** Auto-layout breaks ties by declaration order, so reordering your `d.shape(...)` calls can move shapes, but re-running does not.
- **Pure standard library.** SVG, PDF and BOM need no other packages. PNG is the one output that depends on an installed rasteriser, and its bytes depend on that rasteriser.

```python runnable
from diagrams_as_code import Diagram

def build():
    with Diagram("Same", theme="paper", layout="auto") as d:
        a, b = d.shape("A"), d.shape("B")
        a >> d.edge("x") >> b
    return d

assert build().render_svg() == build().render_svg()
```

## 7. The MCP server: determinism and sandbox limits

`diagrams-as-code mcp --root DIR` serves the tools listed in [`llms-full.txt`](https://bsommers.github.io/diagrams-as-code/llms-full.txt) (generated from the live tool table). What to know before relying on it:

- **It runs scripts, not code strings.** The tools take a *path* to a diagram script under `--root`; there is no tool that accepts Python source. Write the script file first (with your own file tools), then call the tool on its path.
- **Confinement.** Every script path and output path must resolve inside `--root`; anything else is refused, including symlinks that leave it.
- **Resource limits.** Each script runs in a child process with a wall-clock timeout (`--timeout`, default 60 s), a CPU cap, a memory cap on POSIX (`--memory-mb`, default 2048) and no stdin; its stdout is discarded.
- **Not an isolation boundary.** The sandbox does not isolate files or the network: a script can still read and write whatever the server's user can. Run the server in a container if the scripts are untrusted.
- **Same determinism as the library.** Rendering through MCP writes the same bytes as the CLI.
- **Output is capped.** A result longer than 200,000 characters is truncated, and one JSON-RPC message may not exceed 1 MiB.

```python runnable
from pathlib import Path

from diagrams_as_code.mcp import Server

server = Server(Path("."))
listed = server.handle({"jsonrpc": "2.0", "id": 1, "method": "tools/list"})
names = [t["name"] for t in listed["result"]["tools"]]
assert {"render", "lint", "list_themes"} <= set(names)

call = {"name": "render", "arguments": {"path": "hello.py", "out": "mcp_out"}}
reply = server.handle({"jsonrpc": "2.0", "id": 2, "method": "tools/call", "params": call})
assert reply["result"]["isError"] is False
assert Path("mcp_out/hello.svg").read_text() == Path("out/hello.svg").read_text()

outside = {"name": "render", "arguments": {"path": "../hello.py"}}
refused = server.handle({"jsonrpc": "2.0", "id": 3, "method": "tools/call", "params": outside})
assert refused["result"]["isError"] is True
```

## 8. Finding examples

There are hundreds of working scripts. Do not grep the tree; read the index.

- [`examples/index.json`](../examples/index.json): `{"version": ..., "examples": [...]}`. Each record has `path`, `domain`, `number`, `title`, `description`, `theme`, `formats`, `svg` (the rendered file), and the booleans `uses_plot`, `uses_draft`, `uses_sequence`, `uses_gantt`, `uses_math`.
- [`docs/capabilities.json`](capabilities.json): the capability list. Each entry names its Python API, classes, and the test that proves it.
- Every example script `examples/<domain>/NN_name.py` has the rendered `NN_name.svg` and a `NN_name_README.md` bill of materials beside it.

```python runnable
import json
import os
from pathlib import Path

repo = Path(os.environ.get("DAC_REPO", "."))  # the repository root; run from there
index = json.loads((repo / "examples" / "index.json").read_text())
sequence = [e for e in index["examples"] if e["uses_sequence"]]
assert sequence and all((repo / e["path"]).is_file() for e in sequence)
paper = [e for e in index["examples"] if e["theme"] == "paper" and e["uses_math"]]
assert paper
print(sequence[0]["path"], "-", sequence[0]["title"])

caps = json.loads((repo / "docs" / "capabilities.json").read_text())
assert caps["capabilities"] and "python_api" in caps["capabilities"][0]
```

Copy the nearest example, change the content, and keep its `diagram()` / `build_diagram()` shape.
